---
description: Write a plan for a task and wait for approval before changing anything
---

Switch to plan mode and write a plan for: $ARGUMENTS

Include these parts, in as few words as they need:

- **Request**: the task in your own words, so a misunderstanding shows early.
- **Method**: how you would do it, and what one other method would have traded away.
- **Work**: an ordered list. For every entry give the files involved, the kind of change, and any migration, release or
  outside system it touches.
- **Dangers**: what might break and how to undo it.
- **Decisions**: what only the user can settle, or "none".

Add a code sample only where words would be unclear. Make no edits and run no commands that change anything. Show the
plan, adjust it to the user's comments, and begin when they send `/execute` or approve it.
